# Offer 来信局 · P0 使用与修改说明

内容版本：`2.0.0`。2026-11-03 已启用统一兑换码 `1661`。文案与网页验证已完成；发布状态见本次验证记录。

这是一款面向不限专业的校招、实习求职者的完整趣味测试：12 道情境题、每题四选一，生成六种固定的 Offer 剧情。课程作业、社团、比赛、兼职经历都可以代入，没遇到过的情况可以想象作答。

**时间窗口是娱乐剧情设定，不代表真实录用时间。** 同样的完整答案得到同样的结果，不随机抽签，也不按能力高低安排早晚。测试为静态网页，不调用 AI API；上架、收款与发货由你安排。

## 打开网页

- 公开体验地址：<https://offer-letter-mashu.euzj-6912.chatgpt.site/>。
- 无需登录；打开后先输入统一四位兑换码 `1661`，通过后开始测试。同一浏览器记住验证状态，换浏览器或清理网站数据后需要重新输入。
- 本地预览：在项目目录执行 `npm run dev`，打开终端显示的地址。也可以双击 `dist/index.html`。本地地址仅供这台电脑预览。
- 托管时上传 `dist` 目录内的全部文件，以 `index.html` 为入口；无需安装依赖或构建。

## 答题、续答和重测

选完可前往下一题，也可返回修改；完成十二题显示完整结果。结果页可以修改答案，或点击“重新测试”清空本次作答。

进度通过浏览器的 `localStorage` 保存在本机。同一网址、同一浏览器可刷新续答，换设备或浏览器不会同步，清理网站数据后也不能恢复。答案不上传服务器。存储不可用时，本次打开仍可继续作答。

新版题目与旧版语义不同，内容版本提高到 `2.0.0`。旧版本的答案会重置，并提示重新测试，避免把旧选项误当成新版答案。

## 保存来信海报

结果页点击“保存我的来信海报”，打开 **1200 × 1600 像素、3∶4 的 PNG 图片预览**。可长按图片保存，或点击“下载 PNG 海报”。内置浏览器不能下载时，可以尝试长按图片，或在系统浏览器打开同一网址。

桌面 PNG 导出检查不能替代手机相册保存验收。iOS Safari、Android 与小红书内置浏览器的真实手机保存流程仍需手动检查。

## 修改品牌和配置

配置在 `dist/config.js`：

| 字段 | 用途 |
| --- | --- |
| `brand`、`title` | 海报署名和标题 |
| `requireAccessCode` | 当前为 `true`，开启兑换入口 |
| `accessCode` | 统一兑换码，当前为 `1661` |
| `accessRevision` | 验证版本；更换兑换码时一起更新，使旧解锁记录重新验证 |
| `price` | 显示价格，不会创建付款 |

| `posterFilename` | 下载的 PNG 文件名 |

保留引号、逗号和文件结构。网页页眉、浏览器标签和分享元信息位于 `index.html`；开场等固定界面文字位于 `app.js`，调整品牌时一并检查。

## 修改题目和六份结果

确认的文字见交付目录中的 `P0-完整内容稿-六种Offer剧情.md`；网页使用 `dist/data.js` 中的内容。

`questions` 包含 12 道题，每题有 `id`、`chapter`、`title`、`context` 和四个 `options`。每个选项包含：

- `id`：稳定标识。
- `text`：用户看到的选项。
- `insight`：结果页结合用户实际选择显示的解释。
- `scores`：六个非负整数，分别对应六种剧情的权重。

`profiles` 包含六份结果，每份保留以下字段：

| 字段 | 用途 |
| --- | --- |
| `id`、`name` | 剧情标识和称号 |
| `windowLabel`、`windowNote` | 时间窗口和娱乐说明 |
| `tags` | 三个短标签 |
| `quote` | Offer 登场金句 |
| `story` | 三段完整剧情组成的数组 |
| `closing` | 最后一句收尾 |
| `accent` | 预留配色字段 |

六种结果依次为：`arrival` 假装不急型、`pivot` 转个弯捡到宝型、`craft` 认真藏不住型、`connection` 越聊越顺型、`steady` 该投投，该歇歇型、`spark` 顺手试出惊喜型。`scores` 的六个位置严格对应这个顺序。不要单独修改标识或改变结果顺序。

匹配规则将十二次选择的权重分别相加，最高分对应最终剧情；平分按固定结果顺序取首项。结果页再读取两项实际选择，显示对应解释。时间窗口直接取自结果文案，不根据能力、投递量或招聘数据计算。

选项含义改变时，须同步检查 `insight` 和 `scores`，不能只替换选项文字。题目、选项或分数有实质改动时，提高顶层 `version`，让旧记录重新作答。改完文案，应重新检查手机换行和海报排版。
